## 1. Project Overview

Samadhan Suchak reads the text of a customer support ticket and automatically predicts its **category** (for example `ORDER`, `REFUND` or `DELIVERY`) together with a **confidence score**. Tickets the model is unsure about (confidence below 40%) are labelled **"Needs human review"** instead of being guessed. A rule-based suggested reply is also shown for each category (bonus task).

Pipeline:

```
Ticket Description -> Text Cleaning -> Sentence Embedding -> Logistic Regression -> Category + Confidence
```

## 2. Problem Statement

A company receives support requests through email, chat and other channels. Sorting them by hand is slow and error-prone. The goal is to build a basic supervised, multi-class text classification system that learns from historical tickets and predicts the category of a new ticket from its description.

## 4. Dataset Information

- **Name:** Bitext Customer Support LLM Chatbot Training Dataset
- **Source:** Hugging Face – https://huggingface.co/datasets/bitext/Bitext-Customer-Support-LLM-Chatbot-Training-Dataset
- **Records used:** 6,000 rows randomly sampled from the full dataset (`random_state = 42`)
- **Categories (11):** ACCOUNT, CANCEL, CONTACT, DELIVERY, FEEDBACK, INVOICE, ORDER, PAYMENT, REFUND, SHIPPING, SUBSCRIPTION
- **File:** `data/tickets.csv`

| Field | Description | Origin |
| --- | --- | --- |
| `ticket_id` | Unique ticket number | Generated by me |
| `ticket_description` | Customer message | Source column `instruction` |
| `category` | Ticket category (target label) | Source column `category` |
| `priority` | High / Medium / Low | Added randomly (not in source) |
| `status` | Open / Closed / In Progress | Added randomly (not in source) |

**Modifications:** random sampling, column renaming, and the added `ticket_id`, `priority` and `status` columns. `priority` and `status` are random, so they are **not used for training**; they appear only in the exploratory analysis and to match the required CSV format.

## 8. How to Train the Model

Run from the project root:

```bash
python src/train.py
```

This script reads `data/tickets.csv`, removes duplicates and missing rows, cleans the text, splits the data 80% / 20% (stratified, `random_state = 42`), converts tickets to embeddings, trains Logistic Regression (`class_weight="balanced"`), prints the train/test accuracy and classification report, and saves the model to `model/emb_clf.pkl`.

## 9. How to Perform Prediction (Command Line)

```bash
python src/predict.py
```

Type a ticket description when asked. Tickets with confidence below 40% are shown as "Needs human review".

## 10. How to Run the Web Application

```bash
streamlit run src/app.py
```

The browser opens at `http://localhost:8501`. Enter a ticket description, press **Predict**, and the app shows the predicted category, the confidence and a suggested response.

## 12. Results Summary

| Model | Test accuracy | Notes |
| --- | --- | --- |
| TF-IDF + Logistic Regression (first run, 300 rows) | 0.833 (train 0.958) | Overfitting gap of 12.5 points |
| TF-IDF + Logistic Regression (tuned) | 0.933 (train 0.996) | Gap reduced to about 6 points |
| Embeddings + Logistic Regression (final) | 1.00 on the split | 0.73 on 11 hand-written unseen tickets |

The split score is inflated because the Bitext data is template-generated, so the accuracy on hand-written tickets is the more realistic estimate. With the 40% confidence threshold, 10 of 11 test tickets were handled automatically at 0.80 accuracy. See `report.pdf` for the full analysis, confusion matrix and limitations.

## 13. Limitations

- The dataset is template-generated, so the split accuracy is optimistic.
- Only 11 e-commerce categories are supported; tickets from other domains (for example app performance problems) are sent to human review.
- Similar categories such as DELIVERY / SHIPPING and ORDER / CANCEL overlap.
- The test set of hand-written tickets is small (11).
- `priority` and `status` are random and carry no information.
